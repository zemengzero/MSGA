## 输入与输出约定

模块：`frontend/src/noteFind.js`。公开函数：`findInNoteText(text, query)`。

- 两个参数必须是字符串，错误类型抛 TypeError。
- `text` 是**正文预览中可见的纯文本**，不是 Markdown 源码、HTML 字符串或 HTML 属性。该纯函数不访问 DOM、不解析 Markdown/HTML，后续详情组件负责提取可见文字并建立文本节点映射。文字中的链接应使用显示标签，而不是不可见 URL/UUID。
- 将整段 `query` 作为一个字面子串查找，不拆分为全局搜索的多词 AND；输入正则符号也按普通文字处理。
- 中文保持原样，ASCII A–Z 不区分大小写，不扩展为所有 Unicode 字母的大小写匹配，不做 Unicode 规范化。
- 空查询、仅空白查询、空文本、无命中或查询长于文本时返回 `[]`。含非空白文字的查询保留其首尾空格和换行，全文也不折叠空白。
- 返回按位置升序排列的 `[start, end)` 数组，**按 Unicode 码点计数**。保留每个出现位置，包括重叠和紧邻命中，不将其合并，便于后续显示正确命中数及逐处跳转。
- 不截断全文或结果。使用 KMP，时间复杂度 O(n+m+k)，空间 O(n+m+k)，k 为匹配数量；函数无副作用，每次返回新的数组。

```javascript
import { findInNoteText } from "./noteFind.js";

findInNoteText("😀AI😀ai", "ai");
// [[1, 3], [4, 6]]
findInNoteText("ababa", "aba");
// [[0, 3], [2, 5]]
findInNoteText("动态规划与动态规划", "动态规划");
// [[0, 4], [5, 9]]
```

## 后续接入边界

本步函数不会自动把 Markdown 转成可见文字。调用者必须用预览的可见文本作为输入，不能先在 Markdown 源文中匹配再将位置直接套到预览上。跨粗体、链接等行内节点的命中，需要步骤 3 根据同一文本快照映射回多个 DOM 文本节点。

浏览器 DOM Range 的文本节点偏移使用 UTF-16 码元，不能直接套用本函数的码点偏移。后续组件需要显式换算。当前已有的摘要高亮组件接收合并区间，而本函数保留重叠命中；界面渲染时可以合并覆盖范围，但命中数量和当前命中位置应继续使用原始结果，不可直接用合并后的数量替代。

不拼接高亮 HTML，不修改笔记正文。后续高亮应通过安全文本/DOM 标记实现，退出查找或切换笔记时清除临时状态。
