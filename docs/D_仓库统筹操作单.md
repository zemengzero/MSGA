# D今晚的仓库统筹操作单

D固定由已经拿到全员GitHub链接的同学担任。仓库为 https://github.com/zemengzero/MSGA ，验收为2026年11月2日。先确保已有冻结程序能运行，再合并短增量。

## 先用15分钟把协作接通

1. 建一张“姓名/学号/GitHub账号/角色/Issue/PR”表，填写`成员信息.csv`，A/B/C/D各一人。D协调仓库所有者zemengzero配置缺少的协作写权限并让成员接受邀请；公开可读不等于可写。
2. 把Release验收包和仓库地址发给三位成员，让每人先运行“软件/启动演示.bat”。D另找一台无Python的Windows电脑，实际检查启动、保存、重启读回和备份。
3. 认领Issue：A #1–#3，B #4–#6，C #7–#9，D #10–#12。每个任务验收规则与建议提交信息见`团队分工与提交计划.md`。每人约定今晚的完成时间，课前2小时停止新功能。

## 其他三人传给D什么

传**本人账号创建的PR链接**，附测试命令与实际结果、功能截图/简短操作记录、已知限制。涉及界面入口时先找A协调；B优先独立修改备份模块，C优先修改搜索模块，各自在自己的测试文件中补回归。

每人应实际修改、提交并推送，至少三个可运行阶段：功能一→功能二→测试/说明完善。每次都检查diff，不只改提交消息。Git邮箱须关联本人GitHub账号。

只把文件发给D，再由D账号统一上传，不会自动生成其他人的本人提交记录。不要共享密码/令牌，也不要由D替其他人改作者。网络实在不便时可由本人在GitHub网页自己的功能分支提交真实修改，再交D在本机运行验证。

## 合并与冻结

逐个PR查看作者与diff；让另一位成员检查后再合并。优先保留原始提交的合并方式。D在集成版本运行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
python tools/build_exe.py
.\.venv\Scripts\python.exe tools/frozen_smoke.py
```

新成员首次开发先按README创建虚拟环境，安装项目及`requirements-build.lock.txt`。报告工具另需`requirements-docs.txt`；不是所有成员都要装报告依赖。

发布工具读取当前真实证据；修改源码后需重新运行`run_checks.py`、截图/报告与发行校验。现有`publish_history.py`只用于本次网络受限的基线迁移，会拒绝覆盖他人的新提交；后续正常协作直接使用Git/PR，不绕过该保护。

课前1小时四人使用同一冻结exe走一遍8分钟流程。各人打开自己的commit/diff，至少能解释一条“按钮→事件→业务函数→数据库/文件→测试”的路径。未完成的增量留在分支，不影响现场可运行成果。
